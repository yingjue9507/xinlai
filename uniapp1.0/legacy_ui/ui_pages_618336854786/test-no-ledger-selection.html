移除礼簿选择功能测试

🔧 修复内容

问题：添加往来记录页面出现了重复的礼簿选择功能
解决方案：移除礼簿选择器，直接使用传入的礼簿ID

移除的功能：

  • 礼簿选择下拉框
  • 礼簿选择事件处理
  • 礼簿选择验证逻辑
  • loadLedgerOptions函数

保留的功能：

  • 自动根据礼簿类型预选记录类型
  • 无礼簿ID时的错误提示

🧪 测试场景

✅ 正常场景（应该工作）

  1. 打开首页
  2. 点击"记一笔" → 选择礼簿 → 应该直接进入添加页面
  3. 点击礼簿 → 点击"手动录入" → 应该直接进入添加页面
  4. 点击礼簿 → 点击记录 → 点击"添加往来记录" → 应该直接进入添加页面

❌ 异常场景（应该被阻止）

  1. 直接访问添加记录页面
  2. 只带联系人参数访问
  3. 应该显示错误提示并返回上一页

🎯 预期行为

  • 所有从正常入口进入的页面都应该直接进入添加页面
  • 不应该出现礼簿选择下拉框
  • 页面应该根据礼簿类型自动预选"收到"或"送出"
  • 直接访问应该被阻止并提示用户
  • 保存记录应该正常工作，使用传入的礼簿ID

🔗 快速测试链接

正常测试：

1. 首页测试 → 记一笔 → 选择礼簿

异常测试：

2. 直接访问（应失败） → 应显示错误提示 3. 只有联系人（应失败） → 应显示错误提示

正确测试：

4. 带礼簿ID（应成功） → 应直接进入添加页面

📱 用户体验改进

简化流程：
  • 减少了用户的选择步骤
  • 避免了重复的礼簿选择
  • 用户意图更明确（从哪个礼簿进来就在哪个礼簿添加）
  • 防止了用户选择错误的礼簿

⚠️ 注意事项

  • 确保所有入口都正确传递了ledger_id参数
  • 测试无参数访问时的错误处理
  • 验证保存记录功能是否正常工作
  • 检查记录类型是否根据礼簿类型正确预选

💡 修复说明

这次修复解决了用户体验问题，移除了重复的礼簿选择功能，让添加记录的流程更加简洁和直观。用户现在必须从具体的礼簿页面进入添加记录，确保了数据的正确性和操作的明确性。
